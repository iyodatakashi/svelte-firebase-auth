# 実装計画

要件 4.13 は欠番（従来方式からの引き継ぎを行わない）のため、対応するタスクを持たない。

- [x] 1. 基盤: 検証環境と共有の型
- [x] 1.1 Firestore エミュレータを開発・検証環境に加える
  - Auth エミュレータに加えて Firestore エミュレータを起動できるようにし、検証用のセキュリティルール（利用者自身の文書だけを読み書きできる）を置く
  - エミュレータを使う検証の補助に、同じ土台の App から Firestore を取得する手段と、利用者を作る手段を加える
  - Firestore は検証用にだけ使い、配布物の依存に加えない
  - エミュレータの検証を実行すると、Auth と Firestore の両方に接続した状態でテストが走る
  - _Requirements: 7.7_

- [x] 1.2 複数アカウントの公開型と保存の契約を定める
  - 認証の段階に「保持アカウントはあるが選択が無い」段階を、到達判定の結果に「選択待ち」を加える
  - 設定に、複数アカウントに対応するかを指定する必須の項目を加える
  - アカウントの要約、操作の結果と失敗の語彙（上限による失敗・取消・開始失敗を含む）、全件ログアウトの結果、開始時の失敗、ブラウザ保存の契約を型として定める
  - 型検査が通り、新しい型を参照するテストの雛形がコンパイルできる
  - _Requirements: 1.2, 1.3, 7.5, 7.11, 7.19, 4.15_

- [x] 2. 中核: スロット単位の処理と純粋な判定
- [x] 2.1 (P) 1つのスロットの認証処理を内部のストアとして切り出す
  - 現行の認証ストアの処理（購読・サインイン・登録・パスワード変更・確認メール・確認状態の取り直し）を、1つのスロットの Auth を扱う内部のストアへ移す
  - サインアウトは失敗を握りつぶさず、結果を返す
  - 既存のストアの単体テスト・エミュレータテストを内部のストアへ移し、すべて緑のまま通る
  - _Requirements: 2.4, 3.5, 5.6_
  - _Boundary: SlotStore_

- [x] 2.2 (P) 到達判定に未選択の段階を加える
  - 未選択の段階では、サインイン・登録・再設定の経路を許し、確認待ちと保護された経路では遷移せずに選択待ちとする
  - 保護された経路で選択待ちになったときは現在の経路を、確認待ちでは保持中の戻り先を、戻り先として返す
  - 他の段階の判定は変えない
  - design の到達判定の表の全セルを単体テストで確認し、緑になる
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.6, 6.7, 6.8, 6.9_
  - _Boundary: authGuard_

- [x] 2.3 (P) スロット記録の検証と一覧の照合を純関数にする
  - 保存されたスロット記録の形を検証し、版や形の合わないものを捨てる
  - スロットの実際のログイン状態と記録の UID を照合し、一致しないものと未ログインのものを一覧から外す
  - 同じ UID のスロットは ID の順序で代表を決め、選択が重複側を指していれば代表へ付け替える
  - 単一アカウント指定で2件あるときは、後からサインインした方を残す対象として選ぶ
  - それぞれの規則を単体テストで確認し、緑になる
  - _Requirements: 1.3, 2.3, 4.5, 4.9, 7.20_
  - _Boundary: slots_

- [x] 3. 公開の認証ストア
- [x] 3.1 スロットの生成と開始時の復元を実装する
  - 土台の Auth をメモリのみの保存方法に切り替え、選択中スロットの複製か空のどちらかにする
  - 土台の App の設定から名前付き App とその Auth をスロットごとに作り、土台がエミュレータに接続されていれば同じ接続先につなぐ。不要になったスロットの App は破棄する
  - 保存されたスロットを復元し、すべての初回判定と土台の更新が済むまで判定待ちを公開する
  - 土台の切り替えに失敗したとき、および単一アカウント指定でスロットの復元・複製に失敗したときは、開始失敗を公開して判定待ちのまま止める。複数アカウント指定で一部のスロットに失敗したときは、復元できなかったスロットとして公開し、他のアカウントで続行する
  - 停止すると購読を解除してスロットの App を破棄し、ログイン状態は消えない
  - 開始・復元・失敗の各経路を単体テストで確認し、緑になる
  - _Requirements: 1.1, 1.2, 4.1, 4.4, 4.5, 4.10, 4.15_

- [x] 3.2 土台の更新の待ち行列と選択の切り替えを実装する
  - 公開する選択とは別に内部の目標の選択を持ち、土台への複製とサインアウトを1本の待ち行列で直列に実行する
  - 各処理は実行時点の目標を読み、目標のスロットの複製か空にする。完了時に目標が変わっていなければ、選択・利用者情報・アカウントの要約を同じ更新で公開する
  - 切り替えの失敗時は、目標がまだその操作の設定した値の場合に限り元の値へ戻す。その間に届いたログアウト・失効の目標は戻さない
  - 存在しない・ログイン状態を失ったアカウントへの切り替えは失敗として返し、現在の選択を保つ
  - 操作の完了が切り替えの前・途中・後に重なる順序でも、土台と選択が常に切り替え先に揃うことを単体テストで確認し、緑になる
  - _Requirements: 1.3, 3.1, 3.2, 3.3, 3.4, 6.6, 7.6, 7.10, 7.12_

- [x] 3.3 サインイン・登録と取消を実装する
  - どの画面から呼ばれても新しいスロットで認証し、成功したら一覧を確定して土台へ複製し、選択する。明示的な未選択を上書きし、最後に開いたアカウントとして記録する
  - 既に保持している UID なら既存のスロットを選び、新しいスロットを破棄する
  - 失敗・取消では新しいスロットを破棄して元の選択を保つ。取消後に成功が返っても一覧と選択に反映しない
  - 単一アカウント指定で保持アカウントがある間は、上限による失敗として拒否し、既存のログイン状態を変えない
  - 操作中の重複要求は「処理中」として拒否し、操作中の状態と対象を公開する。パスワード再設定メールの送信はアカウントに依らず行える
  - 成功・重複・失敗・取消・上限の各経路を単体テストで確認し、緑になる
  - _Requirements: 2.2, 2.3, 2.4, 2.5, 2.6, 2.8, 4.14, 7.5, 7.11, 7.12, 7.13, 7.19_

- [x] 3.4 ログアウトの全経路を実装する
  - 指定アカウント・選択中アカウント・全件のログアウトを、そのスロットの Auth に直接行い、失敗を対象と理由つきで返す。全件では成功分だけを反映する
  - 別タブでのログアウトや失効を観測した場合も同じ状態更新を行う。一覧から外してスロットを破棄し、選択中なら土台を空にして明示的な未選択を保存し、最後に開いたアカウントが一致すれば消す
  - 残ったアカウントを自動で選ばない。単一アカウント指定では未ログインになる
  - 非選択・選択中・全件・部分失敗・別タブ由来の各経路を単体テストで確認し、緑になる
  - _Requirements: 4.6, 4.9, 5.2, 5.3, 5.4, 5.5, 5.6, 5.8, 5.9, 7.10_

- [x] 3.5 選択中アカウントへの操作を実装する
  - パスワード変更・確認メールの送信・確認状態の取り直しを、呼び出し時点の選択中スロットのユーザーに対して行う
  - 完了後は土台の更新を待ち行列へ積み、実行時点の目標の側を複製し直す
  - 切り替え後に完了した切り替え元の操作が、切り替え先の状態を上書きしないことを単体テストで確認し、緑になる
  - _Requirements: 3.5, 3.6, 3.7_

- [x] 3.6 タブの選択と復元の方針を実装する
  - タブ内の選択記録を優先し、記録が無ければ最後に開いたアカウントを初期選択する。明示的な未選択が引き継がれたときは未選択を保つ
  - 別タブでの選択の変更や最後に開いたアカウントの変更では、現在のタブの選択を変えない
  - 単一アカウント指定ではタブの選択記録を参照せず、保持アカウントがあれば常にそれを選ぶ
  - 保存領域が使えないときはメモリで続け、保存不能を公開する
  - 引き継ぎ・記録なし・明示的な未選択・無効な記録・単一アカウント指定・保存不能の各ケースを単体テストで確認し、緑になる
  - _Requirements: 4.2, 4.3, 4.7, 4.8, 4.11, 4.12, 7.1_

- [x] 4. 画面と到達制御
- [x] 4.1 ブラウザ保存とストアの寿命を扱う部品を作る
  - スロット記録をスロットごとのキーで、最後に開いたアカウントを別のキーで、名前空間付きでブラウザ共通の保存領域に置く。タブの選択はタブ単位の保存領域に置き、記録なしと明示的な未選択を区別する
  - 別タブでのスロット記録の変更を通知する。保存領域が使えない場合は失敗として返す
  - マウントでストアを開始し、アンマウントで停止する
  - 部品を根の配置に置くと、再読み込み後に選択とログイン状態が復元されることをコンポーネントテストで確認する
  - _Requirements: 4.1, 4.2, 4.7, 4.8, 4.9, 4.11, 4.12_

- [x] 4.2 到達ガードを選択待ちに対応させる
  - 選択待ちの判定では遷移せず、保護された子も判定待ちの表示も描画せず、戻り先を保持する
  - 選択されて通過の段階になると、同じ経路のまま子を描画する
  - 未選択の間に保護された内容が出ず、選択後に描画されることをコンポーネントテストで確認する
  - _Requirements: 6.2, 6.3, 6.6, 6.9_

- [x] 4.3 5画面を一本化したストアに合わせる
  - サインイン・登録は新しい結果の型に合わせ、認証の失敗は既存の文言へ、それ以外（処理中・上限など）はアカウントの操作の失敗の文言へ写す（4.4 で用意する写像を共用する）
  - 確認待ち・パスワード変更の画面は選択中アカウントが変わったら作り直し、処理の開始時に控えた選択と完了時の選択が異なるか画面が破棄されていれば、表示の更新と完了通知を行わない。定期的な取り直しは画面の破棄で止める
  - 確認待ち画面のサインアウトは選択中アカウントのログアウトになる
  - 既存の画面のテストを移したうえで、表示中の切り替えで途中状態が破棄され、古い処理の完了で完了通知が呼ばれないことをコンポーネントテストで確認する
  - _Requirements: 2.6, 2.7, 3.6, 5.9, 7.18_

- [x] 4.4 追加と選択の画面の文言を用意する
  - 追加ログイン・アカウント選択・ログアウト・保存不能・上限・処理中の文言を日本語と英語で同梱し、既存と同じく項目単位で差し替えられるようにする
  - 両言語で全項目が揃っていることを型検査と単体テストで確認する
  - _Requirements: 7.4_

- [x] 4.5 (P) 追加ログインの中身のコンポーネントを作る
  - メールアドレスとパスワードの入力、送信中表示、既存のエラー語彙に対応した案内を、ダイアログの外枠や見出しを持たずに提供する
  - 自由登録が許可されていれば登録の入力へ、再設定を求めれば再設定の入力へ同じ領域内で切り替え、追加のサインインへ戻れる。許可されていなければ登録の導線を出さない
  - 成功時は対象アカウントを含む完了通知を、取消時は進行中の試行を無効化して取消の通知を組み込み側へ返す
  - キーボードで操作できる
  - ページとダイアログの内容領域の両方に置き、サインイン・登録・再設定・取消・完了通知をコンポーネントテストで確認する
  - _Requirements: 2.1, 2.4, 2.5, 2.6, 2.7, 2.8, 7.3, 7.15, 7.16, 7.17_
  - _Boundary: AddAccount_

- [x] 4.6 (P) アカウント選択の中身のコンポーネントを作る
  - アカウントの一覧、選択中の表示（色だけに頼らない）、直接切り替え、個別・全件ログアウト、追加の要求を提供する
  - 保持アカウントが無ければ追加の導線を示す。ログアウトをアカウントの削除として表示しない
  - 操作中は競合する入力を止め、失敗時は対象のアカウントが分かる案内を出し、失敗分を再試行できる。保存不能のときは復元できない可能性を示す
  - キーボードで選択・ログアウト・追加を操作でき、各表示をコンポーネントテストで確認する
  - _Requirements: 1.4, 1.5, 4.7, 5.1, 5.6, 5.7, 6.5, 7.3_
  - _Boundary: AccountChooser_

- [x] 5. 統合
- [x] 5.1 公開面を更新する
  - 一本化した認証ストア、ブラウザ保存の部品、追加ログイン・アカウント選択のコンポーネントと、組み込み側が必要とする型を公開する。内部のスロット単位のストアは公開しない
  - 公開面のテストで、公開する名前と公開しない名前が期待どおりであることを確認する
  - _Requirements: 7.2, 7.9_

- [x] 5.2 ショーケースを複数アカウントの組み込み例にする
  - 土台の App から認証ストアを作り、ブラウザ保存の部品を根に置き、複数アカウントを指定する
  - ユーザーメニューを模した入口から、保持アカウントへの直接切り替え・別アカウントのログイン開始・個別ログアウト・全件ログアウトを行えるようにし、選択ダイアログをガードの外に置く
  - 土台の App から作った Firestore で、選択中のアカウントの文書を読み書きする例を置き、切り替えで購読を張り直す
  - 単一アカウント指定で動かす例も置く
  - 開発サーバーでショーケースを開くと、上記の操作がすべて画面から行える

- [x] 5.3 手引きを新しい組み込み方法に書き直す
  - README（英語）を、土台の Auth をストアに委ねること、ブラウザ保存の部品の配置、複数アカウント対応の指定、選択ダイアログの配置、追加ログインとアカウント選択の使い方に書き直す
  - 土台の App からのデータアクセスが選択中アカウントの認証で動くこと、切り替え時の購読の張り直し・表示データの破棄・未送信の書き込みの扱いは組み込み側が行うことを書く
  - 利用者情報のオブジェクトは同じアカウントでも置き換わりうるため、購読の鍵は選択の識別子か uid にすることを書く
  - 起動直後に土台の Auth が空の期間と、開始失敗時の扱いを書く
  - 組み込み側へ返す事項（公開契約・到達判定の変更点）を README と spec に記録し、ショーケースのコードと食い違いが無い

- [x] 6. 検証
- [x] 6.1 エミュレータで土台への複製を確かめる統合テストを書く
  - 2つのスロットへの同時ログイン、片方だけのログアウト、再読み込み後の復元を確認する
  - 選択を切り替えると、土台の App の同じ Firestore が切り替え先のユーザーとしてセキュリティルールに扱われることを確認する
  - 土台を空にしてもスロットのログイン状態が残ること、パスワード変更後に土台の複製が使えること、開始時に土台の Auth が選択中スロットの複製か空になることを確認する

- [x] 6.2 複数アカウントの E2E を書く

  - 2つのタブで別々のアカウントを選び、一方の切り替え・ログアウトが他方の選択に影響しないことを確認する
  - 元のタブから開いた新しいタブと、独立して開いた新しいタブの両方で前回のアカウントが初期選択されることを確認する
  - 選択ダイアログの表示中に保護された内容が見えず、選択後に正しいメールアドレスが見えること、未選択のままサインイン経路でサインインすると選択されて戻り先へ進むこと、確認待ちから別のアカウントへ切り替えられることを確認する
  - E2E がすべて緑になる
