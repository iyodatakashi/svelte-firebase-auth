# Implementation Plan

**画面のテスト 601 行が同時に赤になる期間を短くする。** 判定とガードを先に作り、ガードだけを通しの検証で確かめられる状態にしてから、画面のコールバックを外す。

## 1. 土台

- [x] 1.1 経路の設定を受け取れるようにする
  - SvelteKit を peer の依存として宣言する。**宣言が無いと配布の道具立てが警告を出す**ため、ここで済ませる
  - 認証の経路（サインイン・登録・確認待ち・パスワードの再設定・認証を終えた利用者の既定の行き先）を、設定の必須の項目として受け取る
  - 経路をストアから公開し、画面とガードが**同じ値を読む唯一の出所**にする
  - 経路を与えていない既存の呼び出しは、型検査が漏れなく指し示す
  - 観測可能: 型検査と既存のテストがすべて緑で、経路を欠いた設定が型検査を通らない
  - _Requirements: 1.1, 2.1, 2.2, 2.4_

- [x] 1.2 画面の遷移を確かめられる試験の土台を作る
  - 遷移の呼び出しを、コンポーネントのテストから観測できるようにする
  - **ルーターの無い環境では遷移の関数が例外を投げる**ため、差し替えを試験の設定へ置く
  - 観測可能: 遷移を呼ぶ仮のコンポーネントが、テストで遷移の行き先を検証できる
  - _Requirements: 1.2_

## 2. 到達の判定と、戻り先の保持

判定は**副作用を持たない**。段階・現在の経路・設定・保持している戻り先だけから決まる。

- [x] 2.1 現在の経路が、設定されたどの経路であるかを判定する
  - 経路の部分だけで比べ、問い合わせ文字列を判定に用いない
  - 末尾の区切りを正規化して完全一致とする
  - **前方一致にしない。** 紛らわしい経路（サインインの経路に語を足したもの）を巻き込むと、振り替え先が振り替えの対象から外れる
  - 観測可能: 問い合わせ文字列付き・末尾の区切り付き・紛らわしい経路のいずれでも、正しく判定されることが単体テストで緑
  - _Requirements: 2.5_
  - _Boundary: AuthGuardResolver_

- [x] 2.2 段階ごとの到達の許可と振り替えを決める
  - 初回の判定が済んでいない間は、何も決めない
  - 各段階は**その段階のための経路への到達を許す**。許さないと振り替えが止まらなくなる
  - サインインしていない利用者を振り替えるとき、**振り替えの原因になった経路を戻り先として返す**
  - 条件を満たした利用者が認証の経路にいるとき、保持している戻り先か既定の行き先へ振り替え、戻り先を破棄する
  - 認証の経路そのものを戻り先として返さない
  - 観測可能: 段階4種すべてについて判定が単体テストで緑。**すべての振り替えについて、振り替え先で「留まる」と判定されること**を確かめている
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 5.1, 5.2, 5.3, 5.6_
  - _Boundary: AuthGuardResolver_

- [x] 2.3 (P) 戻り先を保持し、受け入れる値を検査する
  - **根からの相対の経路だけを受け入れる。** 外部を指し得ない形にすることで、照合の書き忘れが起こらない
  - 区切りが2つ続く形（外部として解決される）を弾く
  - タブ単位で、再読み込みと経路の移動を跨いで保持する
  - 保持先が使えない環境でも例外を投げず、戻り先を持たない状態として振る舞う
  - 観測可能: 外部を指す値・空の値・親をたどる値がいずれも弾かれ、確認待ちを跨いでも保持が続くことが単体テストで緑
  - _Requirements: 5.4, 5.5_
  - _Boundary: ReturnToStore_

## 3. 到達の制御

- [x] 3. 判定に従って遷移し、判定が済むまで中身を描画させない
  - 認証の段階と現在の経路の**双方を読む**。どちらが変わっても働く
  - **遷移と描画を対で持つ。** 遷移だけを止めても、判定が済むまで保護された経路の中身が画面に出る
  - 判定が済むまでのあいだに見せるものを、組み込み側が差し替えられるようにする
  - 振り替えを履歴に残さない。残すと戻る操作で振り替え前へ戻り、ふたたび振り替えられる
  - **実行中の振り替え先を保持し、同じ行き先への遷移を重ねて出さない。** 遷移は非同期であり、完了前に段階が変わると二重に走る
  - 組み込み側は、根の配置でこれを1つ置くだけでよい
  - 観測可能: 開発サーバで、未サインインの利用者が保護された経路を開くとサインインへ送られ、**判定が済むまで中身が出ない**
  - _Requirements: 1.2, 1.4, 4.6, 4.7, 4.8_
  - _Depends: 2.2, 2.3_

## 4. 画面が自ら遷移する

5画面は**段階を変えない導線だけ**を自ら遷移する。サインイン・登録・確認・サインアウトの完了は段階を変えるため、到達の制御が動かす。

いずれも公開する型を同じ場所で削るため、**並行して進めない**。

- [x] 4.1 サインインの画面
  - パスワードの再設定を要求する導線が、設定された経路へ遷移する
  - 自由登録が許可されているときだけ、登録の経路への導線を出す
  - **完了時には遷移しない**（到達の制御に任せる）
  - 観測可能: 導線が設定どおりの経路へ遷移すること、許可されていない設定で登録の導線が出ないこと、入力とエラーの提示が変わっていないことがコンポーネントのテストで緑
  - _Requirements: 2.3, 3.1, 3.2_

- [x] 4.2 登録の画面
  - サインインへ戻る導線と、既に使われているメールアドレスのときの再設定への導線が、それぞれの経路へ遷移する
  - 観測可能: 2つの導線が設定どおりの経路へ遷移し、入力を失わせない振る舞いが変わっていないことがコンポーネントのテストで緑
  - _Requirements: 3.3_

- [x] 4.3 確認待ちの画面
  - 別のメールアドレスでの登録し直しが、**サインアウトを終えてから**登録の経路へ遷移する
  - サインアウトの導線は遷移せず、段階の変化に任せる
  - 観測可能: サインアウトの完了より後に遷移が呼ばれること、取り直しの停止と再送の抑止が変わっていないことがコンポーネントのテストで緑
  - _Requirements: 3.4_

- [x] 4.4 パスワードの変更の画面
  - 取りやめが既定の行き先へ遷移する
  - 完了時には遷移せず、完了したことを利用者に示すのみとする
  - 観測可能: 取りやめが既定の行き先へ遷移し、現在のパスワードの誤りの案内が変わっていないことがコンポーネントのテストで緑
  - _Requirements: 3.5_

- [x] 4.5 パスワードの再設定の画面
  - サインインへ戻る導線が、設定された経路へ遷移する
  - 観測可能: 導線が遷移し、登録の有無を示さない表示が変わっていないことがコンポーネントのテストで緑
  - _Requirements: 3.6_

- [x] 4.6 画面の props を共通の基底へ一本化する
  - 画面ごとの props の型は差分が無くなるため、**廃止して共通の基底だけを残す**
  - コールバックの props が公開面に1つも残っていない状態にする
  - 観測可能: 5画面が同じ props の型を用い、コールバックを渡さずに配置できる
  - _Requirements: 1.5, 3.7_

## 5. 公開面とショーケース

- [x] 5.1 公開面をまとめる
  - 到達の制御・生成関数・5画面・文言・型を、**単一の入口**から出す
  - **判定の純関数と戻り先の保持は公開しない。** 到達の制御の内部実装であり、組み込み側が直接使う要求が無い
  - 観測可能: パッケージ名だけで到達の制御・画面・型を取り出せることを、実際に取り出して確かめている
  - _Requirements: 1.3, 1.5_

- [x] 5.2 ショーケースを経路として組み直す
  - 認証の5画面を、それぞれ独立した経路として置く
  - 根の配置でストアを生成し、開始と停止を対で持ち、到達の制御で子を包む
  - **自前の画面切り替えを残さない。** 残すと、ライブラリの遷移と到達の制御を通らない経路でしか確かめられない
  - 観測可能: 開発サーバで、経路を直接開いても到達の制御が働き、5画面すべてを操作できる
  - _Requirements: 6.3, 6.4_
  - _Depends: 3, 4.6_

## 6. 通しの検証と、手引き

- [x] 6.1 ショーケースに対する通しの操作
  - 未サインインで保護された経路を開くと、サインインへ送られること
  - **サインインの後、開こうとしていた経路へ戻ること**
  - 未確認のまま開き直しても、確認待ちを素通りしないこと
  - 判定が済むまで、保護された経路の中身が画面に出ないこと
  - 振り替えの後に戻る操作をしても、振り替え前の経路に留まらないこと
  - サインイン済みの利用者がサインインの経路を開くと、既定の行き先へ送られること
  - 観測可能: 6つの経路が通しで緑
  - _Requirements: 4.2, 4.3, 4.4, 4.6, 4.8, 5.1, 5.2_
  - _Depends: 5.2_

- [x] 6.2 (P) 組み込みの手引きを書き直す
  - 組み込み側が用意する経路と、そこへ置くものを示す
  - 到達の制御を有効にする箇所と書き方を示す
  - 戻り先の振る舞いと、**画面の出し分けを理由にアクセス制御を緩めない**ことを示す
  - ショーケースのコードが配布物に含まれないことを保つ
  - 観測可能: 手引きの記述とショーケースの実装が食い違わない
  - _Requirements: 6.1, 6.2, 6.5_
  - _Boundary: PackagingAndShowcase_
  - _Depends: 5.2_

- [x] 6.3 (P) 方針の転換を記録し、組み込み側へ返す事項をまとめる
  - フレームワークに依存しない方針を、SvelteKit を前提とする方針と**その理由**へ置き換える
  - 先行する spec の、ルーティングに依存しない要件と、遷移をコールバックで返す要件を書き換える。**番号は動かさない**
  - 画面の props の変更を破壊的変更として扱い、組み込み側へ返す事項として残す
  - 観測可能: 置き換えた規則に、条番号ではなく**前提が変わった理由**が書かれている
  - _Requirements: 7.1, 7.2, 7.3_
  - _Boundary: Steering, auth-store-and-screens_
