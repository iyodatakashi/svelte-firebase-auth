# Implementation Plan

依存の向きは `models → messages → screens` と `models → stores → screens`。この順に積む。

## 1. 土台の整備

- [x] 1.1 依存を宣言し、雛形の残骸を片付ける
  - `firebase` / `@14ch/svelte-ui` を peer として宣言し、開発時に使えるよう devDependencies にも入れる（peer は自動で導入されない）
  - `svelte` の peer 宣言はそのまま残す
  - `sv` の雛形として残っている使い捨てのサンプルと demo の経路を消す。**これらは配布物に混ざるため、後回しにしない**
  - 観測可能: 型検査と lint が通り、`prepack` の出力に雛形が含まれない
  - _Requirements: 10.2, 10.5_

- [x] 1.2 実際の Firebase に当てるテストの土台を作る
  - Auth エミュレータの設定を用意し、エミュレータ向けのテストだけを走らせる区分を追加する
  - 起動から実行までを1つのコマンドで行えるようにする
  - 観測可能: 空のエミュレータ向けテストが1本、緑で通る
  - _Requirements: 2.8, 6.1, 7.2_

## 2. 型・語彙・純関数

- [x] 2.1 公開する型を定義する
  - 失敗の語彙（10種）、失敗の値、成功と失敗を判別できる戻り値、設定、ストアの形、5画面の props を定義する
  - **失敗は例外ではなく戻り値で表す**形を、型の段階で確定させる
  - 画面の props は共通の基底から画面ごとの差分だけを足す形にする
  - 観測可能: 型だけで `npm run check` が通り、これ以降の実装が型を参照できる
  - _Requirements: 1.5, 8.1, 8.6_

- [x] 2.2 純関数と、その単体テストを書く
  - メールアドレスの正規化。**組み込み側の照合とアクセス制御が同じ値を得るための唯一の出所**にする
  - Firebase のエラーコードから語彙への写像。未知のコードはその他へ落とす。**コードをそのまま外へ出さない**
  - パスワードの充足状況から、満たしていない要件だけを取り出す。要求されていない項目を理由に含めない
  - 観測可能: 写像表の全エントリと、正規化が冪等であることが単体テストで緑
  - _Requirements: 1.7, 8.2, 8.3, 8.4_

## 3. 文言

- [x] 3.1 既定の日本語と、項目単位の差し替えを用意する
  - 画面に出す文言をすべて1箇所に集める。**コンポーネントに文言を直接書かない**
  - 語彙ごとの案内は、語彙を漏れなく網羅することを型が強制する形で持つ
  - 差し替えは指定された項目だけを置き換え、指定のない項目は既定を残す
  - 観測可能: 語彙を1つ増やすと、既定の文言を足すまで型検査が通らない
  - _Requirements: 9.4, 9.5_

- [x] 3.2 失敗から利用者への文言を引く関数を独立させる
  - **文言を引く分岐はこの関数だけが持つ。** 画面には語彙ごとの分岐もエラーの文言も置かない
  - 分岐は3つ。強度の不足は満たしていない要件から文を組み立て、パスワードの変更の文脈での資格情報の誤りは「現在のパスワードが違う」を返し、それ以外は語彙ごとの案内を引く
  - 観測可能: 語彙のすべてに対して文言が返ることと、パスワードの変更の文脈だけ案内が変わることが単体テストで緑
  - _Requirements: 8.5_

## 4. 認証ストア

- [x] 4.1 生成・購読の寿命・状態の公開
  - 認証インスタンスと設定を外から受け取る。**自身では初期化せず、グローバルな状態を持たない**
  - 購読の開始と停止を対で持つ。開始は冪等にし、停止で公開している状態を初期化する
  - 利用者・サインインの有無・初回判定の完了・正規化済みのメールアドレス・確認済みかどうか・自由登録の可否を公開する
  - **確認済みは利用者の値から導かず、独立した状態として持つ。** Firebase の利用者はクラスのインスタンスで、runes の追随の対象にならない
  - 初回判定の完了は、1回の購読の中では戻らない
  - 観測可能: 開始前は初回判定が未完了のままで、開始すると認証状態に追随し、停止すると更新が止まることが単体テストで緑
  - _Requirements: 1.1, 1.2, 1.3, 1.10, 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 2.11, 4.8, 8.1_

- [x] 4.2 サインイン・サインアウト・登録と、確認メールの送信
  - メールアドレスとパスワードによるサインインとサインアウト
  - 登録は、アカウントを作ってサインイン済みにし、続けて確認メールを送る
  - **確認メールの送信の失敗を、登録の失敗として返さない。** アカウントができていれば成功として返す
  - 確認と再設定の完了後の戻り先を、送信するメールに反映する
  - 確認メールを送る手段を、登録とは別に単独でも提供する
  - **メールリンクに関する API を一切呼ばない**
  - 送信の呼び出しをこの層の内側に閉じ、画面から呼べる形にしない
  - 観測可能: 登録するとサインイン済みになり、確認メールが発行されることをエミュレータで確かめられる
  - _Requirements: 1.6, 1.8, 1.9, 3.1, 3.6, 4.1, 4.2, 5.1_

- [x] 4.3 確認状態の取り直し
  - 利用者の情報と、ID トークンのクレームの**両方**を取り直す。**片方だけでは、画面は進むのに組み込み側のアクセス制御が古い値のまま残る**
  - 実行中の要求があれば、追加の問い合わせをせずその結果を共有する
  - 確認待ち画面以外からも要求できる手段として公開する
  - 観測可能: 重ねて呼んでも問い合わせが1回で済み、確認済みかどうかが返ることが単体テストで緑
  - _Requirements: 2.8, 2.9, 2.10_

- [x] 4.4 パスワードの変更と再設定
  - 変更は、現在のパスワードによる再認証を行ってから新しいパスワードを設定する。完了後もサインイン状態を保つ
  - 失敗した場合は変更前のパスワードを有効なまま残す
  - サインインしていない状態での変更の要求は、Firebase へ問い合わせずに失敗として返す
  - 再設定の要求は、**そのメールアドレスが登録されているかどうかによらず同じ結果を返す**。組み込み先の設定に依存させない
  - 観測可能: 誤った現在のパスワードでは変更されず、未登録のアドレスへの再設定要求が成功として返ることをエミュレータで確かめられる
  - _Requirements: 6.1, 6.4, 6.6, 6.7, 7.1, 7.2_

## 5. 画面

5画面に共通して、ストアを props で受け取り Firebase を直接呼ばない。遷移を自身で行わず、完了と遷移の要求はコールバックで返す。処理中は同じ操作の重複した実行を受け付けず、失敗しても入力内容を失わせない。エラーの文言は 3.2 の関数を呼ぶだけにする。意匠の値は `@14ch/svelte-ui` のトークンを参照し、独自のパレットを持たない。ブラウザ標準のダイアログを使わず、画面全体を占める前提の外形を持たない。

- [x] 5.1 (P) サインインの画面
  - メールアドレスとパスワードの入力、処理中の表示、完了の通知
  - **資格情報の誤りは、どちらが違うかを示さない**
  - パスワードの再設定を要求する導線を常に置く
  - 自由登録が許可されているときだけ、登録を要求する導線を出す
  - 観測可能: 自由登録を許可しない設定では登録の導線が出ず、失敗しても入力が残ることがコンポーネントのテストで緑
  - _Requirements: 3.2, 3.3, 3.4, 3.5, 3.7, 3.8, 3.9, 9.1, 9.2, 9.3, 9.6, 9.7, 9.8, 9.9_
  - _Boundary: SignInScreen_
  - _Depends: 3.2, 4.1_

- [x] 5.2 (P) 登録の画面
  - 既に使われているメールアドレスのときは、その旨を示してパスワードの再設定へ導く
  - 強度が足りないときは、満たしていない要件を示して入力し直せる状態を保つ
  - サインインへ戻る導線を置く
  - 観測可能: 登録済みのアドレスで再設定への導線が現れ、失敗しても入力が残ることがコンポーネントのテストで緑
  - _Requirements: 4.3, 4.4, 4.5, 4.6, 4.7_
  - _Boundary: SignUpScreen_
  - _Depends: 3.2, 4.2_

- [x] 5.3 (P) 確認待ちの画面
  - 送信先のメールアドレスを示し、迷惑メールフォルダの確認を促す
  - 再送・別のメールアドレスでの登録し直し・サインアウトの3つを置く。**登録し直しはサインアウトを終えてから通知する**
  - 表示されている間だけ、一定間隔と前面への復帰を契機に確認状態を取り直す。**表示されなくなったら止める**
  - 再送が受け付けられなくなったら、間隔を空けるよう示して操作を一時的に受け付けない
  - 観測可能: 画面を離れると取り直しが止まり、確認済みになった時点で完了が通知されることがコンポーネントのテストで緑
  - _Requirements: 5.2, 5.3, 5.4, 5.5, 5.6, 5.7, 5.8, 5.9, 5.10_
  - _Boundary: VerifyEmailScreen_
  - _Depends: 3.2, 4.3_

- [x] 5.4 (P) パスワードの変更の画面
  - 現在のパスワードと新しいパスワードを受け取る
  - 現在のパスワードが誤っているときは、その旨を示して新しいパスワードを設定しない
  - 完了を利用者に示し、取りやめる手段を置く
  - 観測可能: 誤った現在のパスワードで専用の案内が出ることがコンポーネントのテストで緑
  - _Requirements: 6.2, 6.3, 6.5, 6.8_
  - _Boundary: PasswordChangeScreen_
  - _Depends: 3.2, 4.4_

- [x] 5.5 (P) パスワードの再設定の画面
  - **登録されているかどうかを利用者に示さない**
  - メールを送ったことと、迷惑メールフォルダも確認するよう示す
  - サインインへ戻る導線を置き、要求が受け付けられなくなったら間隔を空けるよう示す
  - 観測可能: 未登録のアドレスでも登録済みのアドレスでも同じ表示になることがコンポーネントのテストで緑
  - _Requirements: 7.3, 7.4, 7.5, 7.6_
  - _Boundary: PasswordResetScreen_
  - _Depends: 3.2, 4.4_

## 6. 公開面と組み込み

- [x] 6.1 公開面をまとめる
  - 生成関数・5画面・文言・失敗から文言を引く関数・正規化を、単一の入口から出す
  - **公開する値に対応する型を必ず併せて出す。** 組み込み側が型を書けない状態にしない
  - ここに出ていないものは内部実装として扱う
  - 観測可能: 深い経路を書かずにパッケージ名だけで生成関数・画面・型を取り出せる
  - _Requirements: 1.4, 1.5, 8.6_
  - _Depends: 5.1, 5.2, 5.3, 5.4, 5.5_

- [x] 6.2 ショーケースと組み込みの手引き
  - Firebase の初期化・ストアの開始と停止・5画面の切り替えとコールバックの受け方を、実例として書く
  - 手引きには、事前バンドルの除外と `svelte` の重複解決、戻り先のドメインを承認済みに加えること、自由登録を Firebase 側でも揃えることを書く。**画面の出し分けを理由にアクセス制御を緩めない**ことも記す
  - 観測可能: 開発サーバで5画面を実際に操作でき、手引きの記述と食い違わない
  - _Requirements: 10.1, 10.3, 10.4_
  - _Depends: 6.1_

## 7. 実際の Firebase に当てる検証

モックでは書き手の想定しか確かめられない3点に限る。エミュレータが対応しない機能に当たったら、実プロジェクトへ当てるか、ショーケースで実地に確かめる。

- [x] 7.1 (P) 確認済みが ID トークンのクレームへ届くこと
  - 登録から確認メールの発行、別のセッションでの確認、取り直しによる反映までを通す
  - **取り直しの後にクレームが更新されていることを、利用者の値とは別に確かめる**
  - 観測可能: 別セッションで確認したあと、待機側の確認済みとクレームの双方が真になる
  - _Requirements: 2.8, 4.1, 4.2, 5.1_
  - _Boundary: AuthStoreFactory_
  - _Depends: 1.2, 4.3_

- [x] 7.2 (P) 再認証を伴うパスワードの変更
  - 正しい現在のパスワードで成功し、誤った現在のパスワードが資格情報の誤りとして返ることを確かめる
  - 観測可能: 変更後に新しいパスワードでサインインでき、失敗時は元のパスワードが有効なまま
  - _Requirements: 6.1, 6.2, 6.6_
  - _Boundary: AuthStoreFactory_
  - _Depends: 1.2, 4.4_

- [x] 7.3 (P) 未登録のメールアドレスへの再設定の要求
  - Firebase 側の設定によらず成功として返ることを確かめる
  - 観測可能: 未登録のアドレスへの要求が成功として返り、登録の有無が判別できない
  - _Requirements: 7.2_
  - _Boundary: AuthStoreFactory_
  - _Depends: 1.2, 4.4_

  - 観測可能: 3つの経路が通しで緑
